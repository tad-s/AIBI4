# AIBI4 V9 — V8との差分実装メモ

このドキュメントは、V8にはなくV9で追加・変更した実装内容を残すためのメモです。V8を壊さず、V9は `v9/` 配下の独立アプリとして動作します。

## 1. 独立したV9アプリ構成

- `v9/backend/` と `v9/frontend/` を持つ独立構成にした。
- V9用の `v9/Dockerfile` と `v9/railway.json` を追加した。
- RailwayではV8とは別サービスとしてV9を起動する想定。
- FastAPIアプリ名とヘルスチェックのバージョンはV9用に分離している。

主な関連ファイル:

- `v9/backend/main.py`
- `v9/Dockerfile`
- `v9/railway.json`
- `v9/V9_DEPLOY.md`

## 2. ベース分析を6種類追加

V8の既存ベース分析6種類に加えて、V9では以下の分析を追加した。

| No | 分析名 | 主な出力 |
|---:|---|---|
| ⑦ | 注文の流れ | 初期注文から追加注文への流れ、カテゴリ遷移傾向 |
| ⑧ | 売れるメニューの組み合わせ | 同一伝票内で一緒に注文されやすい商品組み合わせ |
| ⑨ | 初期注文の影響 | 最初に注文された商品別の平均商品数・客単価傾向 |
| ⑩ | 注文の連鎖条件 | 商品数帯別の追加注文・高単価化傾向 |
| ⑪ | 時間帯別の違い | 時間帯別の平均注文商品数と平均客単価 |
| ⑫ | 注文が止まるポイント | 商品数帯ごとの継続率・離脱しやすいポイント |

各分析は、グラフ・表・読み取れる知見・アドバイスを返す形式にしている。

主な関連ファイル:

- `v9/backend/analysis_service.py`
- `v9/backend/analysis_router.py`

## 3. チャットの継続・新規送信を分離

V8ではチャット履歴を前提にLLMへ渡すため、連続して別テーマを指示した場合に前回文脈へ引きずられることがあった。

V9では以下を追加した。

- `継続送信`
  - 前回までのチャット履歴をLLMに渡す。
  - 深掘り・補足・再分析に使う。
- `新規チャットとして送信`
  - 過去チャット履歴をLLMに渡さない。
  - 同じ取得データを使いながら、別テーマの分析を独立して依頼できる。
- `履歴クリア`
  - 画面表示とセッション上のチャット履歴・チャット分析結果をクリアする。

APIでは `new_chat` フラグを追加し、`true` の場合はLLM用の `chat_history` と `pending_analysis` を使わない。

主な関連ファイル:

- `v9/backend/chat_router.py`
- `v9/frontend/index.html`
- `v9/frontend/js/api.js`
- `v9/frontend/js/app.js`

## 4. 曖昧なチャット指示への確認フロー

V9では、曖昧な分析指示や現在のデータ構造では直接実行できない指示に対して、すぐに無理なグラフを作らず確認質問を返す処理を追加した。

例:

- 分析軸が不明な場合は、売上・数量・客単価・時間帯・店舗別など、どの切り口で見るか確認する。
- 年齢・性別・会員・再来店など、現在の取得データに存在しない項目を使う分析は代替案を提示する。
- ユーザーが補足回答した場合は、前回依頼と補足回答を統合して分析する。

主な関連ファイル:

- `v9/backend/chat_router.py`

## 5. エビデンスログ出力

V9では、分析結果やチャット出力の根拠確認用にエビデンスログを追加した。

出力対象:

- チャット履歴
- チャットで生成された分析結果
- ベース分析の実行結果
- グラフ生成有無
- 集計テーブルの行数
- 元データの行数・列名
- 実行ステータス
- グラフ生成時のエラー情報

フロントの `エビデンスログ` ボタンからJSONとしてダウンロードできる。

主な関連ファイル:

- `v9/backend/evidence_router.py`
- `v9/backend/analysis_router.py`
- `v9/backend/chat_router.py`
- `v9/frontend/index.html`
- `v9/frontend/js/app.js`

## 6. Excel出力の拡張

V9では、Excel出力に以下を含めるようにした。

- ベース分析グラフ
- チャット分析グラフ
- チャット分析コメント
- 元データサマリー
- エビデンスログ

これにより、画面上の分析結果だけでなく、後から根拠確認できる情報もExcel側へ残せる。

主な関連ファイル:

- `v9/backend/export_router.py`

## 7. V9識別用UI

V8と混同しないように、V9ではサイドバーのブランド表示を変更した。

- 表記を `V9` に変更
- ロゴ色を赤系に変更

主な関連ファイル:

- `v9/frontend/index.html`
- `v9/frontend/css/style.css`

## 8. 既知の前提・制約

- V9の追加分析は、現在取得している伝票・商品明細・時間帯・客単価などの列から推定できる範囲で実行する。
- 実際の注文ラウンドや提供順がデータにない場合、同一伝票内の商品並びや注文時刻から近似する。
- 年齢・性別・会員ID・再来店など、元データに存在しない属性は直接分析できない。
- Railway上ではV8とV9を別サービスとして管理する。既存V8サービスの設定をV9用に上書きしない。

## 9. 運用時の使い分け

- V8:
  - 既存の安定版として利用。
  - 従来の6分析とチャット分析を中心に運用。
- V9:
  - 追加6分析、継続チャット、新規チャット、エビデンスログが必要な場合に利用。
  - 分析結果の根拠確認や、曖昧な分析依頼を対話で具体化する用途に向く。
